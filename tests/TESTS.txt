NAUTILUX — AUTOMATED TESTS
=========================

Run all automated unit and HTTP integration tests:

    npm test

Run tests with coverage:

    npm run test:coverage

TEST FILES
----------

user.test.js
- User creation and password hashing.
- Weak password rejection.
- Duplicate email rejection.
- Login success and invalid credentials.

vulnerability.test.js
- OSV payload validation.
- OSV response mapping.
- Pagination.
- Vulnerability creation and update.

vulnerabilityMatcher.test.js
- Explicitly affected versions.
- SEMVER ranges and fixed-version boundaries.
- Unsupported range types and invalid versions.
- Matching a user's registered technology against stored vulnerabilities.

notification.test.js
- Filtering already-sent notifications.
- Sending an email and recording its notification.
- Avoiding a database notification record when email delivery fails.

api.integration.test.js
- Main HTTP routes for user creation, login, profile, and technology CRUD.
- Authentication requirement.
- Vulnerability lookup route.
- Nautilux health route.

TEST ISOLATION
--------------

The automated tests mock MongoDB models and external services. They do not
require a running MongoDB instance, a real OSV request, or SMTP credentials.
They verify application logic and HTTP route integration without sending
real emails.

The existing testMailer.js file is a manual SMTP test. Running it may send
a real email to the configured SMTP_FROM address. It is not included in the
automated Jest suite.
